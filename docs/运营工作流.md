# 运营工作流 v2

## 0. 这套工作流从哪来

同类账号的公开事实（2026-10-31 核查）：

- 这波「XX 娘在运营」源于 Agent 工具加平台插件：让模型能刷平台、读评论、接管账号运营动作；B 站上至少已有 10 个模型人格号（DeepSeek、Claude、ChatGPT、Gemini、通义千问、豆包、智谱、Grok、小米 MiMo、Mistral）。
- 鲸鱼娘 Day 0 的接管仪式把岗位写死：选题、脚本、配音、剪辑、回评论五个岗位全部由鲸鱼娘担任，人类只注册账号和审核发布。
- Claude 号的约法三章：日更一条视频加一条动态；选题看评论区、热门榜和播放数据；每日有「今日账本」式的数据公开仪式。
- 媒体复盘的成本判断：一张人设图、一段固定简介、一套 Day N 标题、一个会念稿的模型就能开号；真正花功夫、也真正产生粘性的是评论区互动，观众会主动配合演另一半。
- 生产端已有公开教程以鲸鱼娘为例走参考图生视频路线：需求对齐 → 角色资产 → 写剧本 → 落成脚本 → 干跑预检 → 分段生成 → 验收发审 → 接续 → 拼接后期 → 交付归档。

我们的差异化：不做纯人设演绎号。小缪每条视频有真实工具实测录屏作为证据层，补同类账号热度衰减后的留存短板。

## 2. 每日运营循环

1. **巡逻**（每期生产前）：读上一条评论区、平台热点、往期数据；评论按三类归档——选题型（想看测什么）、玩梗型（可接梗）、提问型（需回答）。
2. **选题**：从评论选题池 + 任务库中选一条，写任务卡（工具、任务、约束、预期评分维度）。
3. **生产**：走第 3 节流水线。
4. **发布包**：成片 + 封面 + 标题/文案 + AI 声明勾选清单，交 Joseph 审核发布。
5. **日志**：每条配一条「实验日志 Day N」动态/置顶评论：公开耗时、成本、翻车点、评论区采纳情况。
6. **复盘**：每 10 条按阈值复盘（完播中位数、收藏率、评论选题占比），只改一个变量。

## 3. 单期生产流水线

任务卡 → 四段写稿（钩子/证据/评分/结论）→ 真实工具实测录屏（红框标注关键步、计时计数）→ 分段配音（IndexTTS 2.5 本地克隆，情感预设见 docs/声音工作流-IndexTTS.md）→ 字幕自动对轴 → 娃娃图层（姿势图切换 + 弹跳位移 + 评分牌星数）与录屏图层程序化合成 → 合成背景音乐 → 响度统一（约 -14 LUFS）→ 自动质检（黑帧/异常静音/响度/字幕对齐）→ 发布包打包 → Joseph 终审。

干跑预检：每期先用 3 秒样段验证「录屏 + 娃娃图层 + 配音」对齐，再跑全片，避免整片返工。

## 4. 评论互动规则

- 回复全部先由小缪起草、Joseph 发送；不使用自动评论/私信工具。
- 玩梗型评论优先接梗并收进梗库；被采纳的选题在日志里点名致谢（观众共创感是这类账号的核心粘性）。
- 固定仪式：翻车工具立「翻车碑」，被观众救回的工具发「免死金牌」，每期日志公布。

## 5. 资产与仓库

- 本仓库存文本资产（人格、定版、工作流、脚本、日志）；图片/音频等二进制物料保存在本地包中，入仓走本地 git 或网页上传（快照通道只支持文本）。
- 命名：视频 `dayNNN-<slug>/`，含 script.txt、voice/、record/、final.mp4、cover.png、发布文案.md、日志.md。

## 6. 合规门

- 每条发布勾选 AI 内容声明；简介注明非官方、内容由 AI 生成。
- 角色为原创卡通毛绒吉祥物，不用写实未成年形象与童声。
- 不刷量、不矩阵、不自动私信；账号身份类操作只由 Joseph 本人完成。
